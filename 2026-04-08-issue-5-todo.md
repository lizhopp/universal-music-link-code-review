## Common Pitfalls To Avoid

### Router-level middleware that is too broad

`server/api/users.js` currently applies `requireBody(['email', 'password'])` at the router level.

Why that matters:
- It is fine for `register` and `login`
- It would become a problem if you later add routes like `GET /users/me`

Keep this in mind as the users router grows.

### Duplicating the route prefix

Bad pattern:
- mount `/preferences` in `app.js`
- then also define `/preferences` again inside the router

That would accidentally produce `/preferences/preferences`.

### Mixing structure work with feature work

This issue is about routing structure.

Try not to fold in:
- preferences DB queries
- conversion persistence
- external API integration
- detailed auth guards beyond what is already needed

If you do too much at once, it becomes harder to tell whether a bug is caused by routing, validation, auth, or DB code.
